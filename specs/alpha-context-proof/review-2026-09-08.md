## Constats corrigés

### ACP-T11 — upgrade vers toutes les migrations courantes

Le smoke d'upgrade s'arrêtait à la migration d'août. Il ne reproduisait pas les
migrations de septembre sur une base contenant les données legacy. Le ticket
exige la découverte ordonnée de toutes les migrations, le contrôle du schéma
courant et la conservation des données dans une base jetable gardée.

### ACP-T12 — identité du message et contenu

Après un échec, une nouvelle commande reprenant une identité de message avec
un texte modifié pouvait transmettre le nouveau texte au modèle alors que
l'historique conservait l'ancien. Après succès, elle pouvait renvoyer l'ancienne
réponse sans signaler le conflit. Le contrat de reprise exige désormais un
contenu normalisé identique ; un autre contenu doit être refusé avant tout
nouvel appel/run, tout en conservant la reprise légitime après échec.

### ACP-T13 — transport du harness réel

Le harness Python autonome suivait implicitement les redirections et lisait
les réponses sans plafond. La correction refuse la redirection avant un second
appel et borne la réception, avec une erreur expurgée. Elle ne change ni le
budget ni le protocole de comparaison ; tous les essais de transport sont
simulés ou loopback avec des clés fictives.
